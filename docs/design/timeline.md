# Timeline design

Status: proposed, Nov 14, 2026. The data model is in `crates/engine/src/timeline.rs` (compiles, tested, not yet part of `Document`).

ProCraft's timeline is a track-based animation timeline built on ProCraft's core. This document says what the model is, where it hooks into what already exists, and the order to build it in.

## Goals

- Tracks of clips: a drawing, a group, a video or a sound is a clip with a start and a length. Track order is draw order.
- Every clip carries its own keys (position, scale, rotation, opacity, effect parameters), counted from the clip's own first frame, so a clip can be moved or duplicated without breaking its motion.
- A full easing set (edited in a small easing editor window, not a graph editor), motion paths with Bézier handles, a keyed camera, group clips that cycle, clip mattes, retiming and sync markers.
- ProCraft's own look throughout, in its visual language.
- Keep everything ProCraft does with pixels: textures, parking, undo, the file format, the brush engine.
- Open any existing ProCraft canvas, including Animation Assist ones, without losing anything.

Adjustment layers came in as phase 4 (see Adjustment clips, below); effects stay ProCraft's own suite, with no per-layer effect stack. Audio and video came in as phase 3 (see Media, below).

Left out on purpose (Nov 14, 2026 scope review): a timeline graph editor, stretching clips, scene split and splitting a project, vector in-betweening, and anything else niche. See the gap map for the full list.

## The one big decision: drawings are layers you already have

A timeline could give each drawing (a cel) its own little layer stack, separate from the document's layers. ProCraft has one layer tree, with pixels on the GPU keyed by `LayerId`, least-used layers parked compressed off the GPU, and undo that copies the document structure.

**ProCraft keeps the one layer tree.** A drawing clip names a top-level layer or group in it (`Drawing::root`). The timeline only says when and how each one shows.

Why:

- Textures, parking, undo, saving, layer blend modes, clipping masks, alpha lock, text and vector layers all keep working on drawings with no new code.
- It's exactly how Animation Assist already works (top-level layers and groups are the frames), so migrating is a re-labelling, not a conversion.
- Parking is what makes long animations fit: 240 drawings at 4K is far beyond GPU memory, but only the few near the playhead need textures.

What changes for the layer tree:

- With a timeline, every top-level layer or group belongs to exactly one drawing clip. Nothing else is top-level.
- The layers panel shows the layers of the drawing under the playhead on the selected track, not the whole tree.
- New drawings are new top-level groups; deleting a clip deletes its group (one undo step).

The alternative, a separate per-drawing layer store, would mean a second layer system next to ProCraft's, rewriting compositing, parking, undo and the file format for it. That's the single most expensive way to do this, for no gain the user would see.

## Model

`Document` gets one field, `timeline: Option<Timeline>` (serde default). `None` is a still canvas, exactly as today.

```
Timeline
├─ fps (1–120), duration (frames), exposure (frames per new drawing)
├─ simple: Option<TrackId>       the track shown as a flipbook; None, all tracks
├─ tracks: [Track]              bottom first, like layers
├─ camera: Channel<CameraPose>   center, zoom, rotation
├─ playback, onion skins
├─ media: [Media]               sounds and videos in the package
└─ next_track, next_clip         id counters

Track: id, name, hidden, locked, opacity, clips (time order, no overlaps)

Clip: id, name, start, duration, opacity, blend, mask, adjustment, disabled, label,
      keys: ClipKeys, content:
        Drawing { root: LayerId }
        Group   { tracks, collapsed, cycle: { length, Repeat | ContinueAcross } }
        Video   { media, trim_start, rect }
        Audio   { media, trim_start, offset, volume, muted, volume_keys }

ClipKeys: position, scale, rotation, opacity (Channel each), pivot, adjustment (Channel<Filter>)
Channel<T>: keys sorted by frame;  Key { frame, value, easing, path handles }
Easing: Linear, Hold, Smooth, CubicBezier, Curve, Bounce, Elastic, Steps,
        ElasticSteps, Cyclic, Random, Fitted(easing, repeat), Reversed(easing)
```

Rules:

- **An exposure is a clip.** A drawing held for 3 frames is a drawing clip 3 frames long. An exposure sheet is a run of drawing clips on one track.
- **Keys are clip-relative.** Key 0 is the clip's first frame. Moving a clip moves nothing else; trimming its start shifts its keys so the motion stays put on screen.
- **Masks look one track down.** A clip's mask mode uses whatever clip is on the track directly below at the same frame. With no clip there, the mask does nothing, so moving the clip below never destroys anything. Alpha and luminance mattes stop their source from drawing on its own.
- **Groups have their own time.** Clips inside a group count frames from the group's start. A cycling group plays its first `length` frames again and again; its own keys either repeat each cycle or run on across.
- **Rotation never wraps** (4π is two full turns, so keyed spins play as authored). The camera's rotation does take the short way, since it comes from turning the view.
- **Edge drags** take one of three policies: clamp at the next clip, push everything after along, or trim into the neighbour.

## Sampling a frame

The renderer never walks the model directly. The engine turns a frame number into a `FramePlan` (`Timeline::plan`): a bottom-first list of what to draw.

```
FramePlan { items: [PlanItem] }
PlanItem {
  clip, track,
  shows: Drawing(LayerId)          the drawing's layer subtree
       | Group([PlanItem])         a group's own tracks at its own frame
       | Video { media, seconds },
  local,                           the clip's own frame
  opacity, blend,                  clip opacity times track opacity
  mask: Option<(mode, index)>,     the item on the track just below, when there is one
  matte_only: bool,                consumed by the clip above as a matte
}
Added in 1d: pose: Option<Affine> (None with no pose keys, the fast path), keyed opacity.
Added in phase 4: adjustment: Option<Filter> (an adjustment clip's keyed adjustment there).
```

Groups stay nested in the plan, so the renderer can composite a group as one unit before blending it, with cycles already applied to their frame. Hidden tracks, disabled clips and audio draw nothing. The plan is what tests assert on: "at frame N, this is what's on screen".

The plan is pure engine code with no GPU, so the easing maths, groups, cycles and mattes are all unit-testable.

## Rendering

`gpu::Canvas` already composites a layer subtree (groups are composited on their own when they don't pass through). For a plan:

1. For each `Placed`, composite its subtree into a scratch texture (or use the layer texture directly for a single unposed layer).
2. Draw that with its pose, opacity and blend into the frame. Posed drawing reuses the affine sampling from `transform.wgsl`.
3. Mattes: render the source into a matte texture instead of the frame, then multiply the clip above by its alpha or luminance.
4. Apply the camera when exporting or when the camera view is on.

As built (1f): `Canvas::composite_timeline` walks the plan itself rather than a flattened list. Each depth of group clip has a *reel* of scratch textures (made only when first wanted): a pair a group's own tracks composite onto before the group is laid down as one (posed, faded and blended by its clip), a texture a masked clip is drawn alone on, and two matte textures (a masked clip can be the matte of the one above too). A matte source is drawn alone, at its opacity and pose, onto a matte texture; the clip above is drawn alone and then through it (the layer shader's clip alpha for clipping and alpha mattes, its mask lightness for luma mattes). With the camera on, the whole frame composites onto the top reel's pair first, then goes through the camera's affine onto the canvas, the background staying put under it.

The camera's frame is the canvas's size. `CameraPose::to_frame` maps the canvas into it (the center to the frame's middle, zoomed and turned about it); `Timeline::camera_at` eases its keys with the rotation unwound key to key, so it always turns the short way. A clip inside a group keeps its frames on the group's level: the core API reports and takes timeline frames (adding the groups' starts, `Timeline::origin`), and drawing at the playhead goes through each group's start and cycle (`Timeline::track_frame`, `local_frame`).

Group clips, finished (Nov 15, 2026, `timeline_edits.rs`):

- **Motion paths through groups.** `Timeline::groups_pose` is how the groups a clip is in move, scale and turn it at a frame (their poses, innermost first, in their first cycles). The motion path the iPad draws goes through it, and what is dragged on the canvas comes back through it (`timeline_motion_delta`, and handles given as the path shows them).
- **Into and out of groups.** `move_clip` takes a track on any level (never a group into itself), and a group a clip goes into grows to cover it unless it cycles (`Timeline::cover`). `move_out_of_group` puts a clip on the group's level where it showed (the track above the group's if it has room, else a new one), the group's keys folded into it; `move_into_group` puts it on the group's topmost track with room at its frame. On the iPad a clip dropped onto a group clip on another track goes into it, and an open group's clip pages have Move Out of Group.
- **Ungrouping keeps what the group did.** Its opacity and keys are folded into each clip that comes out: onto a channel the clip has no keys on, the group's go as they are (exact); where both have keys, they are worked out together on every frame either has a key on (a pose about the clip's pivot, turns added and scales multiplied, so only an uneven scale under a turn comes out differently). A cycle is laid out: each clip of the first cycle comes out again for every cycle the group played, cut at the cycle's end and the group's, a drawing's repeats copies of its layers (as far as there is room for layers), the keys repeating or running on as the cycle's did. Clips past the first cycle, which never showed, go on a hidden track. Effect keys, the group's blend mode and mask are let go.
- **Deleting a group clip** takes every drawing's layers in it, in the same undo step, as Cut does.

Onion skins become "the drawings before and after on the selected track", reusing today's `FrameLook::Onion` tinting.

A per-frame composite cache (keyed by frame and document revision) makes scrubbing cheap.

As built (Nov 15, 2026): `gpu::canvas::frame_cache`. Each timeline frame composited whole, with nothing under way (no stroke, smudge, transform, adjustment, held layer or liquify), is kept as a copy of the composite, keyed by the frame and how it shows (drawn on with its onion skins, played, or played through the camera). The "revision" is the frame's own: a fingerprint of everything it was composited from, namely its plan (clips, poses, opacities, blends, mattes, groups), the onion skins on each track, the camera at that frame when it is used, the background, every setting of every layer it draws, and those layers' pixel versions. Going to a kept frame whose fingerprint still holds copies it into the composite instead of compositing it.

Invalidation follows from that, from each frame's dependencies:

- Painting a drawing (and undoing it, or any other pixel change) drops at once every kept frame that draws it, as a clip, a matte or an onion skin.
- A clip, key, camera or settings edit changes the fingerprint of exactly the frames whose plan, skins or camera it changes, and those are composited again when next shown. A camera key changes only frames played through the camera, onion skin settings only frames drawn on.
- What the cache can't see clears it, or keeps a frame out of it: a frame showing a video isn't kept, a change of the canvas's size or format lets everything go, and `Canvas::forget_frames` lets everything go for anything else.

Memory: kept frames are textures the composite's size and format, used again as frames are replaced. When the budget is full, the frame used least lately goes. The budget is per canvas: the iPad sets it to an eighth of the memory the app may use (`set_frame_cache_budget`, next to the layers' quarter), and without one (desktop, the simulator) it is 512 MB.

Scrubbing a 120-frame 1920 × 1080 timeline frame by frame (24 drawings on fives, two onion skins each side, drawn on; the GPU test `scrubbing_120_frames`, release build, Apple M2 Pro), timed until the GPU finishes each frame:

| | ms a frame |
|---|---|
| No cache | 3.1–4.1 |
| First pass, filling the cache | 3.4–3.8 |
| From the cache | 0.66–0.81 |

That is four to five times faster, and the saving grows with what a frame draws: the copy costs the same however many tracks, groups, mattes and posed clips the frame has. The GPU tests in `crates/gpu/tests/frame_cache.rs` compare every frame, in each of the three ways it shows, from the cache against a canvas with no cache, after painting, undo, a clip's opacity, a key, a matte, grouping, camera keys, onion settings, a layer hidden and the background changed, and check which frames each edit sends back to compositing.

## Editing and undo

`Document` is cloned for undo already, so timeline edits are undoable for free. Each user action is one step: moving a clip, setting a key, or adding a drawing (a new group plus its clip).

Drawing on the canvas paints into the drawing under the playhead on the selected track. If there isn't one there, the first stroke makes a new drawing clip with the document's exposure (frames per drawing: on ones, twos, threes and so on).

The core API for the apps (uniffi) is a thin layer: a `TimelineInfo` snapshot for the panel (tracks, clips, key frames), plus commands such as `set_playhead`, `add_track`, `add_drawing`, `move_clip(id, track, start, policy)`, `trim_clip`, `split_clip`, `duplicate_clip`, `set_key`, `remove_key`, `set_easing`, `set_camera_key`.

## Files

The timeline is saved inside the document's JSON as it is. Media goes in the artwork's folder as `media/<id>.<ext>` (see Media).

An older ProCraft ignores the field it doesn't know, so a timeline animation opened in it shows its drawings as plain top-level groups. To keep that useful, ProCraft can also write an Animation Assist block (one frame per drawing on the bottom track, holds from durations). That's a nice-to-have.

## Migrating Animation Assist

`Document::start_timeline` (built in 1a) turns a canvas with Animation Assist settings into a timeline:

- One track, "Animation". Each frame becomes a drawing clip, in order, with its hold as its duration.
- The Background and Foreground options become their own tracks below and above it, with one clip spanning the whole duration. The frame they name is taken off the Animation track, so at its own place in the sequence it shows just as before (behind or in front).
- A hidden top-level layer isn't a frame. It gets a hidden track of its own, so showing it later works.
- Tracks are ordered by where their layers were in the layer stack, so the drawing order is unchanged.
- fps, playback and onion settings (including "blend primary") carry over, and the canvas opens in simple mode.
- `Document::animation` is cleared once the timeline exists.
- Page Assist canvases aren't converted: pages aren't frames.

A canvas with no Animation Assist becomes a one-frame timeline with a track for each top-level layer or group (hidden ones on hidden tracks), so nothing disappears.

The tests convert canvases with holds, a background, a foreground, both, a hidden layer and a single frame, and check that every frame of the timeline shows exactly the drawings Animation Assist showed at that point in its sequence.

When a document is read, `Timeline::repaired` makes the timeline consistent with its layers: a drawing whose layer is gone is dropped (the layers stay), a clip that overlaps the one before it is dropped, no layer is drawn by two clips, and keys are put in frame order. A timeline that can't be read at all is left out rather than failing the document.

## Media (phase 3)

Built Nov 15, 2026: sounds and videos on tracks, and the animatic detector, with an iPad panel.

### Model

The engine keeps what places media in time (`crates/engine/src/media.rs`); the platform decodes and plays.

- `Timeline::media: [Media]`, each `{ id, name, kind (Audio | Video), seconds, extension, size }`. The id is a hash of the file's bytes (`MediaHasher`, FNV over 8-byte words), so bringing the same file in twice shares it. `extension` and `size` are new with serde defaults; a timeline written before media has no `media` list and opens as it was.
- A sound or video clip is an ordinary clip (frames, track, keys), its content `Audio { media, trim_start, offset, volume, muted, volume_keys }` or `Video { media, trim_start, rect }`. Rather than living apart from the tracks and being timed in seconds, a ProCraft sound is a clip on a track like any other, so moving, grouping, cycling, hiding and the track rules all apply with no new code. `trim_start` (where it starts in its file) and a sound's `offset` (a start under a frame after its first frame, for sync finer than a frame) are seconds, so it stays in sync to the sample.
- A clip is never longer than what is left of its file from `trim_start` (`set_duration` clamps). `trim_media_start` drags the left edge (later or earlier in the file, the end kept, never before the file's start or the clip before it); `slip_media` plays another part of the file where the clip is.
- A new sound goes on a track of its own at the bottom (`add_sound`), a new video on one under the drawings, above the sound tracks, fitted into the canvas (`add_video`).
- `Timeline::sounds()` is every sound as it plays in timeline seconds (start, where in the file, how long, level, its volume keys): a group's sounds counted from its start and again on every cycle, cut where the group ends; a hidden track's are muted, a disabled clip's left out. `Sound::gain_at(frame)` is its keyed level.
- The plan's `Shows::Video { media, seconds, rect }` is what a video draws at a frame. It is in `PlanItem`, so `same_shot` (Harmony and sprite sheets) tells video frames apart.
- `Timeline::repaired` keeps the values sane (finite, non-negative trims, volume 0..1, a rect with some size). A clip whose file is missing stays: it plays and draws nothing until the file is back.

### Files

An artwork's folder keeps each file the document plays as `media/<16 hex id>.<ext>`, with a sound's waveform beside it as `<id>.peaks` (little-endian f32s, the loudest sample in each 50th of a second). A file brought in waits in the system temporary folder (`procraft-media/`, named the same way) until a save copies it in. A save moves the files the document no longer plays out to that folder rather than deleting them, because an undo can bring a clip back; `MediaStore` (core) looks in the artwork's folders it was opened from or saved to and then the waiting folder. Nothing about media is in the document's undo copies but the small `Media` records.

### Platform interface

The core never decodes media (`crates/core/src/media.rs`):

- `import_timeline_media(MediaImport { path, name, kind, seconds, width, height, peaks })`: the app reads the length, picture size and waveform; the core hashes and copies the file and makes the clip, one undo step ("Add Sound", "Add Video"), starting a timeline if there isn't one.
- `timeline_sounds(frame)`: the sounds to play, with their files' paths. The app schedules and mixes them.
- `VideoFrames` (a uniffi foreign trait the app implements): `picture(path, seconds, max_side) -> ThumbnailImage`. The GPU canvas (`gpu/src/canvas/video.rs`) holds one texture per video and asks for a new picture only when the time shown changes; it draws it into the clip's rect through the clip's pose, opacity and blend (the transform shader, as a posed drawing is). Exports and Harmony go through the same render, so video shows in them with no more code.
- The animatic detector: `animatic_scores(frames, w, h)` scores grey thumbnails the app decodes, `animatic_holds(scores, sensitivity, shortest)` cuts them, `make_timing_track(clip, holds)` lays the drawings.

### iPad

- `Add` in the panel's header (under Drawing and Track): Sound… or Video from Files…, or Video from Photos… (`TimelineMedia.swift`, `TimelineMediaViews.swift`). A video picked from the Photos library (the system picker, so no permission asked; from iCloud if it is only there) is copied out to a temporary file under the name Photos gives it, brought in as a file from Files is, and the copy removed (the core keeps its own, `PickedMovie`).
- On its lane a sound shows its waveform (the part it plays, in a teal clip; dimmed when muted), a video a strip of film. Picked, the left edge trims into the file and the right edge as any clip's.
- A sound or video's Clip page: the whole file as a strip with the part played lit, dragged to slip; Level and Nudge (the sub-frame offset); Mute; for a video, Fit Canvas / Fill Canvas / Actual Size and Make Timing Track…; Play From the File's Start, Delete.
- Playing: `SoundPlayer` (AVAudioEngine) starts every sound together a moment ahead and the frames are paced by the clock from then, so they stay together; a loop or a jump starts the sounds again from there, and ping-pong's way back is silent. Scrubbing plays the slice of sound under each frame (at least 60 ms).
- MP4 and HEVC exports get the sounds mixed under them (`MediaExport.swift`, AVMutableComposition and an audio mix for the levels); at an export rate other than the timeline's, each sound starts where its frame is shown. GIF and PNG carry no sound.
- Video pictures come from `AVAssetImageGenerator` (within 10 ms of the time asked, scaled to the canvas's longest side).
- Debug scenes: `-screen timeline-sound`, `timeline-video`, `timeline-animatic` make a sound and an animatic on the spot.

### Animatic detector

The animatic detector finds where a video of held drawings (a storyboard or animatic export) changes drawing. Each frame the clip covers is decoded at the time it shows there, shrunk to a grey picture of at most 128 pixels (decoded at twice that and pooled 2×2 to average away compression noise), and compared with the frame before: its score is the share of pixels whose lightness moved by more than 16. Scores are worked out once; a cut is wherever a score reaches the threshold (sensitivity 0 to 1 mapped log-evenly from 0.3, cuts only, to 0.0005, every change), and a cut less than the shortest hold after the last is folded into it (so does a too-short last hold). Make Track lays a new, empty drawing for each hold on a track just above the video, to draw over with the video's timing. The iPad's sheet shows the frame looked at, the scores as bars with the threshold across them and a tick at each cut, Sensitivity and Shortest Hold; both are remembered.

Left out: putting the video's frame as a reference layer under each new drawing ("Include video drawings"); the video stays on its own track under them instead, which shows the same thing without copying pixels.

### Not built: desktop and Android

The engine, core and GPU parts are shared; each platform needs its own decoding and audio:

- **Desktop** (`desktop/`): a `VideoFrames` on a decoder (ffmpeg through a crate such as `ffmpeg-next`, or GStreamer), reading a file's length, size and waveform for `MediaImport`; sound out through `cpal` (or `rodio`), scheduling `timeline_sounds` and following the playhead as the iPad does; a file picker for `+ Media`; muxing the sounds into video exports (the desktop's video export would need to exist first).
- **Android**: `MediaExtractor`/`MediaCodec` or `MediaMetadataRetriever.getFrameAtTime` for `VideoFrames` and the detector's thumbnails, `MediaMetadataRetriever` for length and size, decoding to PCM for the waveform; `AudioTrack` or ExoPlayer clips for playing; `MediaMuxer` for exports.
- Neither has the panel's media UI yet; the core calls are the same.

Keyed levels (Nov 15, 2026): a sound's level is keyed at the playhead from its page (Key Level Over Time, then Level Here and Remove Level Key; `set_timeline_volume_key`, `remove_timeline_volume_key`). `TimelineSound` carries the level on every timeline frame it plays through (`levels`, from `levels_from`; `Sound::levels`): playing sets each player's volume frame by frame, and MP4 and HEVC exports ramp it from each frame's level to the next. Split Here and Duplicate work on sounds and videos too (`split_media`, `duplicate_media`): the rest of a split plays on from where the file was at the cut (a sound's nudge stays with the first piece), its level keys going on from there.

Known gaps everywhere: no recording from the microphone.

## Adjustment clips (phase 4)

As built (Nov 15, 2026). An adjustment layer is a top-level layer like any other, so on a timeline it is a drawing clip's root. That clip is an *adjustment clip* (`Clip::adjustment`, kept in step with the layers by `Document::mark_adjustment_clips` on load and as it is keyed): it draws nothing of its own, but redraws what is under it through its adjustment, for its span, at its clip's opacity.

- **Keys.** `ClipKeys::adjustment` is a `Channel<Filter>`: each key holds the whole adjustment, its kind the layer's. `Filter` is `Keyed`, so the timeline's easings (every one, the easing editor's too) ease it value by value from key to key; choices that change in steps (a halftone's kind, a vignette lightening) are the first key's. Keys of another kind than the layer's (the layer changed since) are left out of the drawing, and let go when it is keyed again.
- **Plan and renderer.** `PlanItem::adjustment` is the keyed adjustment at that frame (none without keys). The compositor draws an adjustment layer with it in place of its own. The frame cache's fingerprint takes the plan whole, so a keyed change is a new frame.
- **Keys panel.** The picked clip's adjustment values show under its pose as plain rows (`Filter::params`: each value's name, range and unit), at the playhead. Sliding one keys the whole adjustment there, a new key easing as chosen; "Remove Keys Here", copying, pasting, retiming and the easing editor take adjustment keys with the others. No graph: the user chose plain parameter lists.
- **Not keyed:** curves and gradient maps' tables, kinds and on/off choices, and a blur's region (on a timeline, a blurring adjustment layer still composites the whole canvas, since its keys can change how far it reads).

## Panel: direct manipulation (first pass)

*The strip and tracks views this pass and the next describe were deleted on Nov 22, 2026, with markers, the drawn loop range, the edge-policy choice and snapping. What follows is kept for the engine behaviour it introduced; the panel is the grid (third and fourth passes).*

As built (Nov 15, 2026), after reviewing the iPad panel: the full view's first group of gaps.

What happens at the next clip is chosen in Settings (`EdgePolicy`): **Stop** at it, **Push** the clips beyond that edge along with it both ways (the start's as far as the first of them has room), or **Trim** into it down to its last frame. Push is where it starts. While an edge is dragged the tracks neither scroll nor zoom, and a second finger's taps and drags on them do nothing else.
- **Engine** (`timeline_trim.rs`, `Timeline::trim`): a start dragged takes the clip's keys along so its motion stays where it showed; a group's own clips stay where they showed (so its start goes no later than the first of them); a sound or video starts later or earlier in its file. The header then offers Group, Copy, Duplicate (copies as far along as all of them span on the timeline, so they keep their timing with one another, on each level from the lowest of its picked tracks up, the clips there moving along, a group growing to hold its copies and pushing the clips after it on along (`Timeline::grow_groups_pushing`; a cycling group's cycle grows to hold them instead, playing as many cycles as before), each drawing a copy of its layers, the copies picked; picked clips may be on several levels, inside unfolded groups and out: `duplicate_timeline_clips`, one undo step), Cut and Delete (`delete_timeline_clips`, one undo step) and Done. Held and dragged on, the name lifts and moves up or down among the tracks of its level, an accent line where it will land (`Timeline::move_track`, `move_timeline_track`): it then draws over the tracks below it, and its clips are masked by the track now below.
- **Solo.** A track's checkbox held, or Show Alone, shows it alone: every other track hidden but those holding the group it is in (so it can draw), the tracks inside its own groups left as they are, one "Solo Track" step (`Timeline::solo`, `soloed`; `solo_timeline_track`). - **Key lanes** (`TimelineKeyLanes.swift`). Each channel's keys are their own: picked on one lane, the keys on the others' same frame stay. A key moved onto another of its lane's takes its place. A drag shows what it would do from a copy (`timeline_keys_edit_preview`) and is one undo step when let go (`edit_timeline_keys`: Move Keys, Stretch Keys, Reverse Keys, Remove Keys, Easing), on however many lanes; a drag the system takes away (the app sent to the background, say) shows no more and does nothing. A locked track's keys stay put while the rest go. The Keys page's "Remove Keys Here…" takes one channel's key or every channel's. Debug scenes: `timeline-lanes`, `timeline-lanes-sound`.

- **Extend** (Nov 16, 2026). A clip, or the clips picked together, each made to last through the empty frames after it on its track: up to the next clip there or, with none after it, to the end of the timeline (a group's own inside a group, one cycle of it if it cycles), a sound or video no further than its file (`Timeline::fill_out`, `extend_timeline_clips`, one "Extend Clips" step). - **Onion skins' page** (Nov 16, 2026). The settings show one Onion Skins row (how many show each side); the counts, opacity and colours are on a page it opens in the settings' place (`OnionSkinsPage`).
- **Autokey** (a keyframe mode). `Autokey` in the full view's header turns it on (red, a dot before it) and opens the transform tool; turned off, a transform keying a pose ends with its keys kept. While it is on (for the canvas's session; it starts off) and nothing is selected, the transform tool on a timeline keys the pose of the drawing at the playhead on the track drawn on rather than moving its pixels (`timeline/autokey.rs`, `set_timeline_autokey`). The box is laid around what the drawing paints, where its keys and the groups it is in show it there. Each step of a drag keys only the channels it changes (a move Position, a corner or edge Scale, the rotate node Rotation) at the playhead, shown at once; the drag let go, or a toolbar change (flip, Rotate 45°, Fit, Reset, numbers typed in), is one "Key" undo step. A channel's first key on a frame after the clip's first also keys its first frame with the value it had there, so what leads up to the playhead stays put. A key already there keeps how it eases; a new one eases as the Keys page's easing. The first pose key sets the pivot to the middle of what the drawing paints, as the Keys page does. Distort and Warp act as Freeform (a pose doesn't bend or skew), the node that turns the box alone does nothing, and Pixelated is let be. The transform's undo takes back the keys it made, one step at a time, and nothing from before it. Moving the playhead lays the box again over the drawing there (`timeline_autokey_box`). Ending the transform keeps the keys; cancelling it puts back every clip it keyed as they were as it began, as one more step. A red badge over the canvas says the frame being keyed; tapped ("Turn Off"), autokey goes off and the transform ends with its keys kept, since the transform's toolbar stands over the header's Autokey. With a selection, the selected pixels move as ever. A group or video clip picked in the panel and playing at the playhead is keyed in the drawing's place (`set_timeline_autokey_clip`): a group's box is laid around what it shows there, each drawing in it as its own keys and the groups between pose it, taken back out of the group's own pose; a video's around its picture. Picked but not at the playhead, the drawing there is keyed as before. Changing the Keys page's easing reaches autokey at once (`set_timeline_autokey_easing`). With autokey on, the clip page's opacity reads "Opacity, Keyed Here": it shows the opacity at the playhead and keys it there (`autokey_timeline_clip_opacity`, one "Key Opacity" step a drag, its first key after the clip's start keying the start with what it had) rather than setting the clip's own. They unfold to start with; the chevron on the clip, a double tap, or Fold Group on its page folds them away (`Group::collapsed`, `set_timeline_group_folded`, kept with the canvas, not an undo step). Their clips sit where they play on the timeline (in a cycling group, its first cycle), so they are picked, moved, trimmed, snapped and moved to another row (into a group or out) as on any track (`timeline_rows`, in place of `timeline_tracks` in the panel). Outside the frames its group plays them in a row is shaded, and where a cycling group plays them again their repeats show dashed and faint. A track holding the group locked, its rows' clips stay put too. A picked cycling group's end grip sets how long it plays: dragged, it grows or shrinks a frame at a time, snapping (within 10 points) onto each whole cycle's end with a tick of haptics, a tag reading ×3, or ×2 +1 where it stops a frame into a cycle, up to the next clip on its track; let go, one "Cycles" undo step (`Timeline::group_room`, `set_group_span`; `timeline_group_room`, `set_timeline_group_length`; whole counts still through `cycles`, `set_cycles`). A last cycle may be cut short, as the Cycle slider could already leave it. Its start stays put, as before. While a group clip is dragged, its unfolded rows (and those of the groups inside it) follow it.
- **Playback and length** (`TimelinePlayback.swift`). The ruler held a moment and dragged draws the looped frames from where it was held to the finger (one "Loop Playback" step on letting go, the scrub standing aside meanwhile); each end of the band has a grip, dragged frame by frame and never past the other end or off the timeline, set on letting go. The timeline's end has a tab on the ruler, dragged longer or shorter down to a frame, the ruler shading past it as it goes (a firmer tick as it passes the clips' end), one "Length" step on letting go (`Timeline::set_length`, `set_timeline_length`: the looped frames kept within it, markers past it dropped, the playhead kept on it). It may end before its clips: what is past the end stays where it is on its track, shaded over the lanes with a line at the end (`TimelinePastEnd`), and the lanes reach a little past the last clip so it can still be picked and dragged; it doesn't play (playing goes round the timeline's frames), export or take the playhead. Moves and trims leave the length as it is, so a clip can be parked out there; what adds clips (a new drawing, sound or video, a duplicate, a paste, more cycles) still grows it to hold them. Onion skins come from the drawings either side on the track wherever they are. Settings' Length takes the same rule. ◀︎ and ▶︎ beside Play go to the start of the drawing before or after the playhead on the track drawn on (a group counts; sounds and videos don't). The frame counter, or a tap on the end tab or a loop grip, opens the **Frames** page: the length in frames and seconds; **Fit to Content** (`fit_to_content`, `fit_timeline_to_content`, the length set to the last clip's end, shorter or longer); a count of frames (a second's worth to start with) added **at Start** or **at End** (`add_frames`, `add_timeline_frames`, one "Add Frames" step: at the start every clip on the timeline's own tracks, the camera's keys, the markers, the looped frames and the playhead move along, a clip's own keys, a group's clips and a sound's place in its file going with it); **Loop What Shows** (the frames the tracks show, read from their scroll view), **Loop This Group** while one is open, and stopping the loop. A group clip picked loops from its Clip page, as any clip does.
- **Panel refresh** (`timeline/panel.rs`, `TimelineBigDebug.swift`). After a change the panel reads everything it shows in one call (`timeline_panel`): the settings, its rows, every clip's keys, the camera's and each sound's volume keys, the markers, the clipboard, the looped frames, the onion skins, and a version of each drawing's picture (made from the canvas's size and the version, opacity and showing of its layers). The core numbers each reading and keeps the last: asked with the number the panel has, it answers nothing when nothing in it changed. The panel then sets only the parts that differ, so the views showing the rest aren't made again, and draws again only the pictures whose version changed (before, every read drew every drawing's picture). Measured in the simulator (`-screen timeline-big`, 89 drawings on 20 tracks, each keyed; Debug app, release core): a read with the panel shown kept the main thread busy 90 ms before, 12–20 ms after (the playhead moving every other read); each read drew all 90 pictures again before (about 770 ms of drawing, holding the canvas, so a read made just after another waited 22 ms for it), none after; a drawing cleared draws that one picture again, and so does undoing it.

## Panel: the grid (third pass)

As built (Nov 21, 2026). The iPad shows every timeline as a grid (`TimelineGrid.swift`, `TimelineGridCells.swift`, `TimelineGridMenus.swift`), in place of both the simple strip and the tracks view, which are no longer shown (their code is still in `TimelineBar.swift` and the files beside it, unreached). The model, the core's calls and `TimelineTool` are the same.

- **Look.** A dark card: Play and a frame back or on, then the lasso, a new track and a new frame; a ruler of frame numbers; a row of frame cells a track (40 × 31 points, 44 from one to the next), the tracks' names in capsules standing still over the cells, which fade out under them. A drawing held for more than a frame is one block, its first frame as it is and the held ones shaded. A group, a sound or a video is a plain block with its name. The accent is the interface's own.
- **Playhead.** An outline in the middle of the bar on the chosen track's row; the frames slide under it. Dragged sideways they scrub, and settle on a frame when let go; a frame tapped slides under it. It may rest on an empty frame up to 64 past the timeline's end (`rest_timeline_frame`; `set_timeline_frame` still keeps within the timeline): nothing shows there until something is drawn or added, which makes the timeline that long.
- **Lasting longer.** The frame under the playhead, tapped, is outlined whole with a handle on each edge. A handle dragged makes it last longer or shorter, shown as it goes from `timeline_lengthen_preview`, one "Trim" step when let go (`lengthen_timeline_clip`, whatever edge policy was last chosen in the tracks view). An end pushes the frames after it along, the timeline growing to hold them (trims otherwise leave its length alone, which would leave frames past its end). A start dragged earlier pushes the frames before it earlier, the nearest first, into the empty frames before them (`Timeline::close_up_before`; `EdgePolicy::Push` would move every one of them together and stop as soon as the first is on the first frame); with no more room there, the frame lasts as much longer at its end instead, the frames after it pushed along, so it gets as long as was dragged either way. A start dragged later leaves the frames before it where they are. Held at a limit (a frame is at least one long; a start at the frames packed before it), a line stands down the tracks there.
- **Picking together.** The lasso turns select mode on: a stroke drawn across the frames picks each one it crosses, on any track; empty frames aren't picked. The last picked frame has the handles: dragged, every picked frame changes by as many frames (`lengthen_timeline_clips`: `trim_clips` pushing, the timeline growing to hold them; their starts are still pushed together, as `EdgePolicy::Push` does), the handle going as far as the frames before it on its track grow. One of them held opens their menu: cut, copy, paste, duplicate, **Flip frames** (`Timeline::reverse_clips`, `reverse_timeline_clips`: each mirrored across the frames they span, so they play in the opposite order; refused where one would land on a frame that isn't picked), **Clear frames** (`clear_timeline_clips`: a new empty layer in each drawing's place, the clip, its length and keys kept) and delete.
- **Menus.** A frame held: cut, copy, paste, duplicate, Insert frame, Fill duration (`fill_out`), Frame duration, Track options, Clear frame, Delete frame. A track's name held (or Track options): cut, copy, paste and duplicate for every frame of it, opacity, rename, **Highlight**, **Blend mode**, **Mask**, lock, delete. Deleting frames never takes a track away.
- **A track's look** (`Track::look`: `TrackLook { label, blend, mask }`, serde default). The highlight colours the track's capsule. The blend mode and mask are those of its clips that have none of their own (`Track::blend_of`, `mask_of`, used by the plan and the onion skins), which, since a track's clips never overlap, is a track's blend mode and mask; a clip's own, set in the tracks view before, still wins. `set_timeline_track_label`, `_blend`, `_mask`.
- **Touches.** One drag gesture on the rows tells a tap, a drag sideways (scrub), a drag up or down (more tracks than show), a stroke and a handle apart. A finger held still comes from a press recognizer of UIKit's (`GridHoldProbe`), since SwiftUI's drag says nothing of a finger until it moves.
- **Settings** (frame rate, playback, onion skins, frames per new drawing, length) open from Actions → Canvas → Timeline Settings, the grid's header having no word for them.
- **Not in the grid** as this pass left it: keys and easing, the camera, markers, looped frames, a sound's or group's own page, zoom, snapping and the edge policy (see the fourth pass for what came back).
- Debug scenes: `timeline-grid`, `timeline-grid-held`, `timeline-grid-select`, `timeline-grid-menu`, `timeline-grid-track`.

## Panel: the grid, part 2 (fourth pass)

As built (Nov 21, 2026), after nine points of review and three more recordings. What the grid's first pass left without a way to edit it is back in the grid's own manner, bar the camera (which still plays and exports, and has no row yet) and markers (taken out of the panel; a file's own stay in it, unread). The old strip and tracks views were deleted the day after (see the end of this section).

- **Sizes and rows** (`TimelineGridRows.swift`). Nothing in the grid is a fixed number of points any more: `GridSizes` gives a cell's and a row's size at a zoom, and `GridRows` where each row stands. A row is a track's, or, under a track holding expanded groups, a row those groups' tracks share (`GridSegment`: a track and the frames its group lasts), or a row of keys.
- **Zoom** (`TimelineGridZoom.swift`). Two fingers on the frames zoom about the playhead and carry the frames and rows along as they move together (`GridPinchProbe`, a recognizer that follows two touches from the moment the second lands, and recognizes nothing). Zoomed out, a cell and a row shrink together down to half; further out, the frames alone narrow, to where the whole timeline shows on either side of the playhead (never under 0.75 points a frame); zoomed in, the frames alone widen, to twice. A pinch closing fast as the fingers lift (the canvas's own `QUICK_PINCH_SPEED`) eases back to the size the grid starts at; one flung open eases out to where everything shows. The ruler writes every frame's number while they fit, then every second, fifth, tenth… with a tick at the rest, then the seconds. Under 20 points a frame the drawings' pictures go; under 5 the empty slots are one strip. Kept (`timelineGridZoom`).

The motion path shows over the canvas for the block under the playhead while Animate is on or its track's rows of keys are out.

## Decisions

Settled Nov 14, 2026:

- **Frame rate:** 1–120 fps (`MAX_FPS`).
- **Simple mode stays.** `Timeline::simple` names the one track a document shows as a flipbook strip, like Animation Assist today: one thumbnail per drawing, holds as widths, onion skins, play. `None` is the full track view. Both are views of the same document, so switching never changes it, and the other tracks (a background, say) still draw in simple mode. A migrated Animation Assist canvas opens in simple mode on its "Animation" track.
- **Effect keys** were stored as plain parameter lists by effect id (`Channel<Vec<f32>>`) until phase 4 defined the effect types. As built (Nov 15, 2026), they are typed: one `Channel<Filter>` per clip, an adjustment clip's adjustment. Old files' `effects` lists were never written to, and are dropped on load.
- **Exposure is one setting per document** (`Timeline::exposure`, frames per new drawing, 1 to 12, default 1 for "on ones").
